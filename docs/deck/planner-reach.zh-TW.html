問到「沒指名的那一台」，規劃器會怎麼做

同一種問句，三個階段。/ask 的計畫是在任何查詢跑之前一次寫完的——這一件事決定了哪些題答得出來。

以前— 08-30 之前
「哪一台機台的誤判最多？」
它產生的計畫
—拒答：「沒有工具可以不指名機台查」
—或自己挑一台去查，答得像真的

prompt 只教它「參數必須是存在的值」，沒教它「集合很小的時候可以整個掃一遍」。所以沒指名的題，它要嘛不敢動，要嘛猜。

這不是模型笨。它被交代的是「不要編造不存在的機台」，而「把整個集合掃一遍」是另一件事，從來沒有人跟它說過可以。

現在— 08-30 起
「哪一台機台的誤判最多？」同一句話，沒有改題目
它產生的計畫
1排序：全部機台的誤判率
2查 M11 的細節
3查 M22 的細節
…prompt 裡列出的機台，每一台各一次

機台、線別、班別、事件種類都列在 prompt 裡，而且數量小。規則因此是「排序一次 ＋ 每個成員各查一次」：仍然一次規劃，同時展開。

兩條煞車：一個工具就排得完的題不准拆成六個查詢；板子、批號、複判人員不是列出的集合，照樣拒答。

「最差的那台機台，最近有沒有發生什麼事？」
它想產生的計畫
1排序：全部機台的誤判率
2查 <第一步的第一名> 最近的事件
✕第二步要用第一步的答案，而計畫早就寫完了——這條通道不存在

計畫在第一個查詢跑之前就寫完了，所以第一步的結果沒有地方可以流回計畫裡。模型的反應是寫一個佔位符，或乾脆拒答。

兩種現在都會被擋下來（驗證擋佔位符、守門擋 b.id='這片'），所以頁面顯示「規劃不出來」，不是一個看起來像答案的空答案。
