# AOI-Agent 使用 SOP

給第一次坐到這台複判站前面的人。整份照著做一遍大約 15 分鐘；
要當示範用，第 2 到第 6 節就是示範的順序。

## 這個系統做什麼（一句話）

AOI 在每片 PCB 上標出的紅框，只有四成是真的瑕疵。這個系統先用一個
視覺模型把明顯的誤報排掉、明顯的瑕疵確認掉，剩下看不準的才交給人——
而且交給人的時候，旁邊附著證據和一段說明。

你在這裡做的事只有一件：**看它交過來的區域，告訴它你的判定。**
你的答案會變成下一輪訓練的標籤，所以它記名字、不給你看標準答案。

## 0 · 開機前的三個檢查

| 檢查 | 怎麼看 | 不對的話 |
|---|---|---|
| Ollama 活著 | `ollama ps`，列出 `gpt-oss:20b` 或空的都可以 | `launchctl kickstart -k gui/$(id -u)/local.ollama` |
| 沒有人在佔 GPU | `lsof -nP -iTCP:11434` 只有 ollama 自己 | 等它跑完，或問持有的人。翻譯工作在跑時，每段說明會從 30 秒變成幾分鐘 |
| 站台開著 | 瀏覽器開 <http://aoi.test> 看到登入頁 | `uv run python -m aoi_agent station`（在 `~/Projects/aoi-agent`） |

## 1 · 登入

帳號是名字，密碼是通行碼。兩種身分：

- **一般作業員**（例：`watcher`）：可以判所有正常的區域
- **資深**（例：`mike`）：多一件事——可以判別人按過「我不確定」退回來的區域

站台上方會顯示你的名字，你按的每一個答案都記在這個名字下。

## 2 · 讓一片 PCB 跑過系統

終端機：

```bash
uv run python -m aoi_agent board 20085294 --queue
```

畫面會列出這片板子上每個紅框的結果，三種：

| 結果 | 意思 | 誰決定的 |
|---|---|---|
| `DISMISSED` | 誤報，排掉 | 視覺模型，幾毫秒 |
| `DEFECT` | 瑕疵，確認 | 視覺模型，幾毫秒 |
| `escalated … left on the review station's queue` | 看不準，交給人 | 進待複判清單，附一段 agent 寫的說明（中文約 30 秒） |

一片板子大約 10–30 個紅框，通常八成以上是前兩種，剩下的進清單。

## 3 · 待複判（你每天主要待的頁面）

進站台第一頁就是。每一列一個區域，從左到右：

- **區域**：板號 `#` 序號
- **模型判定 / 信心 / P(誤判)**：模型認為它是什麼、多有把握、有多像誤報
- **產線 / 機台 / 班別**、**等候起點**（UTC）
- **為什麼交給人**：agent 寫的兩句摘要，「展開全文」看整段

等最久的在最上面。按右邊「複判」或最下面「從第一件開始」。

### 一個區域怎麼判

進到區域頁，由上往下：

1. **AGENT 交出來的理由**：它看到什麼、傾向什麼、為什麼沒把握。
   旁邊如果有黃色小標「N 個數字不在證據裡」，代表這段話裡有數字是
   它自己編的——判定不受影響，但那幾個數字別當真。
2. **三張圖**：黃金樣板、待測 PCB、差異圖。紅框是 AOI 標的位置。
3. **三欄證據**：模型讀到什麼（含它實際看的 64 px 小圖）、
   產線脈絡（這台機的缺陷率對比全廠）、檢索到的驗收標準。
4. **你的判定**：按鍵盤 `1`–`7`（false_call、open、short、mousebite、
   spur、copper、pin-hole）或點按鈕。答完自動跳下一個。
5. **看不出來？** 底下填一句「哪裡看不出來」（可留白），按 `0`。
   它**不會**被記成判定，區域會移到「待資深複判」。

需要量比例的類別（mousebite、spur、copper）：差異圖上方「重新量測」
可以拉線量比例，讀數會記在你的判定上。

**一條規則**：不確定就按 0，不要猜。猜錯的答案跟專家的答案在資料庫裡
長得一模一樣，之前刪過五筆。

## 4 · 待資深複判

被按過 0 的區域在這裡，被越多人退回的排越前面。只有資深身分登入
才會看到判定按鈕；一般作業員開這頁只會看到一行說明。

這頁是清單不是派工——沒有人會收到通知，要有人固定來看。

## 5 · PCB 處置

整片板子的紀錄。上面四個數字：**已定案 · 扣住 · 放行 · 等待中**
（等待中 = 還有區域在待複判或待資深複判，所以整片還不能定案）。

點「看紀錄」進單片頁：每個區域是誰判的（模型 / agent / 人名）、
用哪個模型（SHA-256）、哪個程式版本、什麼時候。稽核員問的問題都在這一頁。

## 6 · 產線查詢（/ask）

給主管問問題的地方。打一句話，例如：

- `L2-M22 的 open 是不是不尋常？該停機嗎？`
- `M32 參數變更前後，open 的比例有沒有變？`
- `比較三條線的缺陷組成`
- `A 班今天標了幾個區域？`

先按「這一頁能回答什麼」看它會什麼、不會什麼——**它不改資料、不做預測、
不判斷原因；沒有資料的日期直接說沒有，不會拿附近的日子代替。**

送出後大約 25–40 秒，頁面上會有六個區塊，照這個順序讀：

| 區塊 | 看什麼 |
|---|---|
| 1 它怎麼理解你的問題 | 它把你的話翻成了什麼。理解錯了，下面全錯 |
| 2 它假設了什麼 | 你沒說清楚的地方它怎麼補的（例：「最近」= 7 天） |
| 3 它呼叫了什麼 | 查了哪幾張表、參數是什麼、每個花幾毫秒。「查無資料」的橘標代表那一路是空的 |
| 4 圖 | 從結果自動畫的；柱上有數值，有區間就有鬚線。**兩根柱的鬚線重疊 = 沒證明有差** |
| 5 回答 | 文字。上方若有「數字核對：N 處對不上」，先看第 3 區的原始資料再讀 |
| 6 花了多久 | 規劃、查詢、畫圖、撰寫各幾秒，「等待」和「模型推論」差很多就是機器在忙別的 |

它寫 SQL 的時候（工具答不了的問題才會），那句 SQL 會印在結果旁邊。
唯讀、單句、兩秒、看不到答案欄。

**切語言**：右上角。介面和答案會換語言；你打的問題和它的理解、假設
**保持原文並標示**，因為那是紀錄。答案是從同一批數字重寫的，不是翻譯。

## 7 · 看到這些代表什麼

| 畫面上 | 意思 | 你要做的 |
|---|---|---|
| 「無說明」小標 | 模型逾時 / 沒開 / 回了讀不懂的東西；判定照舊 | 照三張圖和證據判；累積多了看第 8 節 |
| 「N 個數字不在證據裡」 | agent 說明裡有它自己編的數字 | 那幾個數字不要信，其他照讀 |
| 「查無資料」 | 那一路查詢回來是空的 | 看第 3 區它查了什麼；通常是問題沒指名 |
| /ask 直接拒答 | 問的東西資料裡沒有、或問法對不上 | 看它列的原因，換個問法 |
| 產線查詢很慢（>60 秒） | GPU 被別的工作佔著 | 第 0 節第二項 |

## 8 · 收工前的三個指令

```bash
uv run python -m aoi_agent queue          # 還有幾件在等人
uv run python -m aoi_agent explanations   # 多少判定沒有說明、各是什麼原因
uv run python -m aoi_agent provenance 20085294   # 這片是誰判的、哪個模型
```

## 9 · 當示範用的順序

第 2 節跑一片 → 第 3 節開一個區域、給足 40 秒、按 0 → 換一般帳號
看按鈕消失 → 第 5 節四個數字 → 第 6 節現場問一題、再開一題問過的
→ 切語言。詳細分鏡與旁白在 `docs/demo-script.md`。

## 不在這份 SOP 裡的

- **重新訓練模型**：作業員的判定累積到夠多才做，另有程序（`.claude/skills/retraining-the-reverifier`）。
- **加帳號**：`uv run python scripts/add_operator.py <名字> [--role senior]`。
- **產線資料是模擬的**，驗收標準是本專案自撰，不是 IPC-A-610。站台每一頁都有寫。
